# Markdown project memory (INPROOM-35)

A **memory snapshot** is a Markdown document of a project's sources and their freshness, its decisions, facts and approved links, generated from INPROOM's knowledge.
- **Every line cites the item it came from**, for example `[jira:PAY-17@3]` (the kind, the item and the revision). Citations resolve through `POST /v1/projects/{id}/provenance/resolve`.
- Snapshots are **versioned**, **reproducible** and **never a source**: nothing in INPROOM reads a snapshot back as knowledge.

## What a snapshot contains

| Section | Rule (also stated in the document) |
|---|---|
| Sources and freshness | Every source of the project, with its trust tier and sync health (`fresh`, `stale`, `failing`, `paused`, `never`) |
| Decisions | Confluence pages labelled `decision` or `adr`; pages, documents and issues titled `ADR-n…` or `Decision…`; Jira issues labelled `decision`. **Approved** when from an authoritative or trusted source, **proposed** when from a reference or untrusted one. Each has the first sentence of its Decision section, or of its first passage |
| Facts | **Authoritative and trusted sources only:** Jira issues nested under their parents (type, status, components, versions), code owners per repository branch (CODEOWNERS), and pages and documents by title. Reference and untrusted items are counted, not asserted |
| Links | **Approved links only:** stated by a source system (validated), confirmed by a curator, or added by one. Unconfirmed inferred links are counted, not listed |
| Freshness warnings | Sources whose sync is stale or failing, and items still awaiting graph extraction |

Trust tiers come from source policies ([provenance.md](provenance.md)), and the graph from [knowledge-graph.md](knowledge-graph.md). Explicit approval records (E06) will feed the same sections.

## Reproducible by construction

The body contains **no clock and no sync timestamps**. Those change with every sync even when no content does, so they go to the snapshot's `metadata` (for example `sources_as_of`).
- Ordering is total.
- The generator version (`memory@1+secrets@1`) is pinned.
- The sha256 of the bytes is stored.

Consequences:
- **Create is idempotent.** If the generated bytes equal the latest version's, `POST` returns that version (200, `created: false`) instead of storing a duplicate. Creations of one project are serialized, so concurrent retries cannot fork versions.
- **Verify** regenerates from current knowledge without storing anything. It reports `reproducible: true` when the bytes (and generator) match, or the `drift` as a unified diff.

## Access over time

A snapshot never extends anyone's access:
- **On every read**, a line naming an item that is no longer visible is **withheld**. That covers restricted at the source, deleted, paused, over the classification cap, uploads disabled, or another tenant or project. `withheld` counts such lines, and `served_sha256` is the digest of what was served. A restored item's lines show again.
- **A line depends on every item it names.** A link names two items, and a nested Jira issue names its parent. If any of them is hidden, the line is withheld.
- **Purge deletes** the lines of purged content from the database, in the purge's own transaction (`memory_lines_deleted` in the `content.purged` event). The version's stored `sha256` keeps describing what was generated.

## Secrets

Before anything is hashed or stored, every rendered string passes the scrubber (`app/content/secrets.py`, rules version 1). It replaces each of the following with `[REDACTED:<type>]`:
- private keys;
- AWS and Google keys;
- GitHub, Slack and Atlassian tokens;
- `sk-…` API keys;
- JWTs and bearer tokens;
- credentialed URLs;
- `password=` / `secret:` / `api_key:` assignments.

`redactions` counts them by type; the secrets themselves are never stored. UUIDs, git shas, hashes and prose such as "password policy" are left alone. A rule change bumps the generator version, and `verify` then reports drift until a new version is created.

## API

| Method | Path | Permission | Notes |
|---|---|---|---|
| POST | `/v1/projects/{id}/memory/snapshots` | project.memory.publish | `{reason}`. Returns 201 with a new version, or 200 with the identical latest version. Audited as `memory.snapshot.created` |
| GET | `/v1/projects/{id}/memory/snapshots` | project.read | Versions, newest first |
| GET | `/v1/projects/{id}/memory/snapshots/{version}` | project.read | JSON (`markdown`, `served_sha256`, `withheld`, `citations`), or `?format=markdown` (text/markdown, with `ETag` set to the served sha256 and `X-Memory-Withheld`) |
| GET | `/v1/projects/{id}/memory/snapshots/{version}/diff?against=n` | project.read | A unified diff from `n` to `version`, plus per-section added and removed counts (both as served) |
| POST | `/v1/projects/{id}/memory/snapshots/{version}/verify` | project.read | `{reproducible, sha256, current_sha256, generator, current_generator, withheld, drift}`. Read-only |

`project.memory.publish` belongs to project admin, product owner, tech lead and QA lead.

Errors:
- `MEMORY_SNAPSHOT_NOT_FOUND` (404);
- `PROJECT_ARCHIVED` (409, on create);
- 422 for a missing `reason` or `against`.

## Operating

| Symptom | Cause and action |
|---|---|
| `verify` reports drift right after creating | Knowledge changed in between (a sync, a review, a visibility change), or the generator was upgraded. Create a new version if the change should be recorded |
| `withheld` > 0 on an old version | Items it cites became hidden after it was taken. This is expected. Create a new version for a current view |
| A decision is missing | Label the page `decision` or `adr`, or title it `ADR-n …` or `Decision …`. From an upload it shows as *proposed* unless the upload source policy is trusted |
| A fact is missing | Its source's trust tier is `reference` or `untrusted`, so it is counted, not asserted. Change the source policy if it should be authoritative |
| `[REDACTED:…]` in a title | A credential was found. Remove it from the source; the next version is clean |

**Telemetry:** each create logs `memory snapshot project=<id> {"version", "created", "bytes", "counts", "redactions", "ms"}`. It never logs content.
