Four reproduced defects
=======================

QA-28-1 — High: ambiguous citation anchors (AC 1).
Location: apps/api/app/content/parsing/model.py, Builder._anchor / Builder.heading.
Input: Markdown headings A, A, A-2, each followed by body text.
Actual: anchors [a, a-2, a-2]. Two sections have the same citation target.
Expected: unique anchors throughout a document.
The heading path is also ignored when constructing anchors: adding Beta/Setup
before Alpha/Setup changes Alpha/Setup from setup to setup-2 despite its unchanged
path and text. The story specifies heading-path slugs.
Recommendation: derive anchors from the heading path and reserve every emitted
anchor globally, including generated suffixes and the preamble anchor.
Probes: test_anchors_do_not_collide_with_numbered_headings;
test_heading_path_anchors_survive_inserting_another_branch.

QA-28-2 — High: table content bypasses the parser's text budget (AC 2, 5).
Location: apps/api/app/content/parsing/model.py, Builder.table.
Input: a single HTML or Markdown table cell containing 10,000,001 ASCII x's.
The input fits the default 25 MiB upload cap.
Actual: parse succeeds despite exceeding MAX_TEXT_CHARS=10,000,000.
Expected: PARSE_LIMIT_EXCEEDED. The runbook explicitly promises this limit.
Only Builder.text increments the budget; table cells and headings do not.
Recommendation: account for all emitted text, including cells and headings,
and enforce budgets before allocating large intermediate results where possible.
Probe: test_table_text_is_subject_to_the_real_text_limit (HTML and Markdown).

QA-28-3 — Medium: valid heading-only documents fail as empty (AC 1, 2).
Location: apps/api/app/content/parsing/model.py, Builder.result.
Inputs: '# A useful title'; '<h1>A useful title</h1>'.
Actual: EMPTY_DOCUMENT, because the emptiness check ignores heading text.
API reproduction: upload title.md -> 201; run derive jobs; GET document ->
409 NOT_PARSED, parse_status=FAILED, failure=EMPTY_DOCUMENT.
Expected: READY document containing the heading and its anchor.
Recommendation: count nonempty headings when determining whether a document
contains text. Cover DOCX heading/title-only documents as well.
Probes: test_heading_only_documents_are_not_empty (Markdown and HTML);
test_heading_only_upload_can_be_read_as_a_document.

QA-28-4 — Medium: nested HTML tables silently lose content (AC 1).
Location: apps/api/app/content/parsing/formats.py, _Html cell/table handling.
Input:
<table><tr><td>Before<table><tr><td>Inner</td></tr></table>After</td>
<td>Sibling</td></tr></table>
Actual: retained table cell text is only 'Sibling'; Before, Inner and After
are absent from the parsed table. The parser reports success without a warning.
Expected: retain the enclosing cell text and nested table text, or explicitly
report unsupported/truncated structure rather than silently dropping it.
Recommendation: maintain a cell buffer with each nested table frame and merge
the nested result back into its enclosing cell in reading order.
Probe: test_nested_html_table_keeps_every_cell_text.
